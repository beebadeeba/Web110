Key Issues When Introducing AI

Ethics, bias, and fairness

AI systems are trained on historical code, datasets, or web content, and can reproduce biases. For example: because there is so much media descrediting the achievements of POC, the AI could learn and replicate these biases, creating unfair outcomes. Recommended content or decision made by the AI may disadvantage particular groups if training data is skewed. Ethical review and diverse datasets are necessary to avoid amplifying these problems.

In a professional setting, bias audits and add extra security measures, such as explainability logs and rollback options should be implemented by any team using AI; so their AI-produced outputs can be traced and corrected. Regulation on algorithmic fairness is increasing, so documenting datasets and decisions is especially important when relying on 3rd party information.

Practically, a bias mitigation step should already be in any given team's deployment checklist: But when using AI, an extra test with sample users can prevent any bias from the AI.

Security & dependency risks

AI tools often introduce integrity risks. Using external APIs for code completion or generation means secrets and code context might be sent to third parties.

Maliciously crafted prompts or poisoned training samples can cause undesirable behavior. Using security practices like isolating model access, sanitizing inputs, and (in a professional setting) requiring human review for critical outputs can help mitigate these dangers.

Plan for service outages: when you rely on an AI 3rd party to create or maintain your code or website, you must build fallbacks or failsafes so your site continues to operate if an AI service becomes unavailable.

TL;DR

  1. Bias is prevalent in media - therefore will be prevalent in the data AI trains from.
  2. AI can introduce malicious or poisoned content because it is trained on user data, and people can purposefully poison the AI's database
